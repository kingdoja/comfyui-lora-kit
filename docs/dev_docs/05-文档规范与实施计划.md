# 文档规范与实施计划

## 后续开发文档怎么写

每个任务目录都应自带文档，避免只靠代码理解业务。

推荐每个任务至少包含：

- `README.md`：任务目标、安装方式、入口节点、使用示例。
- `NODE_SPEC.md`：节点输入输出、字段含义、默认值、错误提示。
- `API_SPEC.md`：前端调用的 HTTP 接口。
- `DATA_SCHEMA.md`：JSON、manifest、caption、训练配置格式。
- `WORKFLOW_GUIDE.md`：工作流 JSON 的 Group 说明和使用方式。
- `TEST_PLAN.md`：验收用例、失败场景、模型缺失场景。

文档命名以中文业务名为主也可以，但节点名、字段名、路径名建议用英文，减少 ComfyUI/Python 兼容问题。

## 开发顺序

### 阶段 0：目录和骨架

- 新建 3 个自定义节点目录。
- 每个目录只注册一个最小可见节点。
- 新建 3 个工作流目录。
- 新建 `README.md` 和节点说明。

验收：ComfyUI 能看到 3 个 Ninebot 分类下的节点。

### 阶段 1：资产库 MVP

- 上传图片。
- 保存元数据。
- 生成缩略图。
- 分类、标签、caption、评分编辑。
- 资产选择节点输出图片和 caption。

验收：能从资产库选图给后续工作流使用。

### 阶段 2：LoRA 生图 MVP

- 列出 checkpoint、LoRA。
- 选择尺寸、prompt、seed。
- 无 ControlNet 纯 LoRA 生图。
- 保存生成结果和参数。

验收：模型齐全时可生成图片；模型缺失时错误清晰。

### 阶段 3：ControlNet 接入

- 识别 `models/controlnet/` 模型。
- 支持 canny、depth、hed、mlsd、normal_map、openpose。
- 做预处理器缺失和模型缺失校验。

验收：不同 ControlNet 类型能跑通，且结果参数可追溯。

### 阶段 4：LoRA 训练 MVP

- 资产库数据集转训练集。
- 自动生成 caption。
- 人工复核 caption。
- 调用外部训练脚本。
- 输出 LoRA、样张、训练报告。

验收：小数据集可以完成一次端到端训练，并在生图任务中加载生成。

### 阶段 5：体验整合

- 前端面板接近设计图里的上传、快捷按钮、生成按钮。
- 增加 prompt 优化和意图按钮。
- 工作流 Group 标注完善。
- 资产库、训练、生成之间互相跳转。

验收：业务用户不需要理解底层复杂节点，也能完成“上传素材 -> 训练 LoRA -> 选择 LoRA 生图 -> 结果入库”。

## 风险与处理

- 训练硬件风险：`AdamW8bit` 需要 CUDA/bitsandbytes，Mac 环境可能不可用。处理方式是启动前检查并提供 fallback。
- 模型文件风险：当前 ControlNet 和 checkpoint 基本为空。处理方式是所有模型选择都做空状态和路径提示。
- 训练阻塞风险：训练不能在 ComfyUI 主线程同步执行。处理方式是 job queue + 日志轮询。
- 数据污染风险：所有运行数据写入 `user/ninebot_*`，不混入现有文件。
- 节点过大风险：高级节点只暴露业务参数，复杂逻辑放服务层和工作流。

## 工作流 Group 标注规范

Group 名称使用序号加业务目的：

```text
1. 素材上传与资产选择
2. 提示词优化
3. 模型与 LoRA 加载
4. ControlNet 预处理
5. 采样生成
6. 保存结果与入库
```

颜色建议：

- 输入/资产：蓝色。
- 模型加载：紫色。
- 预处理/ControlNet：橙色。
- 采样：绿色。
- 输出/保存：灰色。

## 第一轮交付物建议

第一轮不要直接做完整训练平台，先交付可演示闭环：

1. 资产库可上传和选择 10 到 30 张图。
2. LoRA 生图节点能加载已有 LoRA 和 checkpoint。
3. ControlNet 先支持 canny 和 depth 两个最常用类型。
4. LoRA 训练先完成配置生成和任务状态，再接真实训练脚本。
