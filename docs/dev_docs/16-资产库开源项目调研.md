# 资产库开源项目调研

调研日期：2026-06-30

## 结论

GitHub 上有接近 Ninebot 资产库需求的项目，但没有一个项目可以直接替代本项目的设计。

现成项目主要覆盖四类能力：

1. ComfyUI 生成结果图库。
2. 本地 DAM / 媒体资产管理。
3. LoRA / 模型资产管理。
4. Workflow 模板浏览和加载。

Ninebot 资产库需要把这些能力整合到 ComfyUI 左侧面板中，并增加品牌素材分类、图片角色、工作流模板、参数预设、生成结果回收入库、模型资产索引。因此推荐继续自研 `custom_nodes/ninebot_asset_library/`，同时借鉴成熟项目的局部设计。

## 1. SmartGallery DAM

地址：

```text
https://github.com/biagiomaf/smart-comfyui-gallery
```

定位：

本地优先、浏览器式 Digital Asset Manager，支持 ComfyUI 和任意媒体文件夹。它可以独立于 ComfyUI 运行。

可借鉴：

- 本地优先 DAM 思路。
- 大量文件的 SQLite 索引和搜索。
- 按 prompt、model、LoRA、comment 搜索。
- 评分、评论、状态标签。
- 虚拟集合。
- workflow template / remix 相关设计。
- Docker 化和跨平台部署思路。

不建议直接复用：

- 它不是 ComfyUI 左侧面板。
- 重点是生成结果和媒体资产，不是 Ninebot 品牌素材入口。
- 不负责把素材点选/拖拽到 ComfyUI 节点。
- 不覆盖 Ninebot 的图片角色体系：设计图、构图、颜色质感、logo。

建议：

作为 DAM 数据层和搜索体验参考，不作为直接依赖。

## 2. ComfyUI-Gallery

地址：

```text
https://github.com/PanicTitan/ComfyUI-Gallery
```

定位：

ComfyUI 内的实时 output gallery，可查看图片、视频、GIF、音频、3D 模型，支持元数据查看、搜索、排序、移动、下载。

可借鉴：

- ComfyUI 内嵌 gallery 的扩展方式。
- output folder 监听。
- 实时更新。
- 图片 metadata 提取。
- 生成结果媒体预览。
- 搜索排序和下载操作。

不建议直接复用：

- 它的主对象是 output 文件，不是业务素材库。
- 不管理图片 roles、workflow template、preset、模型资产索引。
- 不覆盖素材回填到业务节点的交互。

建议：

重点研究 `server.py`、folder monitor/scanner、metadata extractor、web UI 的组织方式。生成结果回收入库阶段可参考。

## 3. ComfyUI-Sidebar-Gallery

地址：

```text
https://github.com/TokenSpender/ComfyUI-Sidebar-Gallery
```

定位：

ComfyUI 侧边栏图库，索引 output folder 和附加目录，读取生成元数据并展示为可搜索面板。

可借鉴：

- 左侧/侧边栏媒体浏览体验。
- SQLite 索引。
- 缩略图按需生成。
- 大量文件搜索和分页。
- 结构化元数据展示。
- 支持 ComfyUI、Automatic1111、Forge、SD.Next、Fooocus 元数据解析的思路。

不建议直接复用：

- 项目很新，稳定性需要观察。
- 聚焦图片/视频 output，不覆盖模型资产、workflow 模板、预设。
- 缺少 Ninebot 业务分类和资产角色。

建议：

作为 Ninebot 左侧面板和索引实现的轻量参考。

## 4. ComfyUI-Lora-Manager

地址：

```text
https://github.com/willmiao/ComfyUI-Lora-Manager
```

定位：

ComfyUI LoRA 管理扩展，支持组织、预览、集成 LoRA 模型，并带 metadata 和 workflow 支持。

可借鉴：

- 模型扫描和索引。
- LoRA 预览图。
- 触发词管理。
- recipe / 组合应用。
- 一键集成到 workflow。
- standalone web UI + ComfyUI widget 双界面结构。
- 大规模模型库性能处理。

风险：

- GPL-3.0 许可证，需要避免直接复制其代码进入 Ninebot 商业/内部项目，除非能接受许可证传染约束。
- 项目功能较大，直接引入会改变 Ninebot 资产库边界。
- 聚焦 LoRA，对 checkpoint / ControlNet / 图片素材 / 工作流模板不是完整解法。

建议：

借鉴模型资产 Tab 和 LoRA 元数据字段设计，不直接复制代码。必要时可以选择兼容它的 metadata，而不是依赖它。

## 5. ComfyUI workflow_templates

官方文档：

```text
https://docs.comfy.org/interface/features/template
https://docs.comfy.org/custom-nodes/workflow_templates
```

官方仓库：

```text
https://github.com/Comfy-Org/workflow_templates
```

定位：

ComfyUI 官方 workflow 模板体系。自定义节点可以提供 `example_workflows/`，ComfyUI 会在模板浏览器中展示这些 JSON，可选同名 JPG 缩略图。

可借鉴：

- workflow JSON + thumbnail 的结构。
- `example_workflows/` 命名约定。
- 模板浏览器加载方式。
- 模板仓库的分类和 manifest 思路。
- 后续可以让 Ninebot 官方示例工作流同时出现在 ComfyUI 原生模板浏览器中。

不适合直接替代：

- 官方模板体系是通用模板浏览，不是 Ninebot 业务资产库。
- 不管理收藏、发布状态、参数预设、素材角色、生成结果回收入库。

建议：

Ninebot 工作流库应保存自己的业务 metadata，同时导出一份 `example_workflows/` 兼容 ComfyUI 原生模板浏览器。

## 对 Ninebot 方案的影响

原设计保持不变：

```text
Ninebot 资产库 MVP
= 图片素材库
+ 模型资产索引
+ 工作流模板库
+ 参数预设
+ 生成结果回收入库
```

但实施计划中建议增加一个 Phase 0.5：

```text
Phase 0.5：开源项目源码对照
```

目标：

- 阅读 SmartGallery 的索引和搜索实现。
- 阅读 ComfyUI-Gallery 的 output 监听和 metadata extractor。
- 阅读 ComfyUI-Sidebar-Gallery 的 sidebar UI 和 SQLite index。
- 阅读 ComfyUI-Lora-Manager 的模型扫描、触发词和 widget 集成。
- 阅读 ComfyUI workflow_templates 的 example_workflows 结构。

交付：

```text
custom_nodes/ninebot_asset_library/docs/14_SOURCE_REUSE_NOTES.md
```

该文档记录哪些设计借鉴、哪些代码不能直接复制、哪些字段需要兼容。

## 复用策略

推荐策略：

```text
设计借鉴为主
接口兼容为辅
代码复制谨慎
核心业务自研
```

具体规则：

- MIT 项目可以参考实现，但仍应优先重写 Ninebot 自己的轻量版本。
- GPL-3.0 项目只借鉴思路和字段，不复制代码。
- 对外部项目不要形成运行时强依赖，避免 ComfyUI 版本和第三方更新导致资产库不可用。
- 能用 ComfyUI 官方机制的地方优先兼容官方机制，例如 `example_workflows/`。

## 更新后的开发建议

在正式进入编码前，增加以下短调研任务：

1. Clone 或下载上述项目到临时 research 目录。
2. 记录各项目许可证。
3. 截取可借鉴模块路径。
4. 对照 Ninebot 文档更新字段命名。
5. 决定是否兼容 SmartGallery 或 Lora-Manager 的 metadata。
6. 决定工作流模板是否同步导出到 `example_workflows/`。

建议结论：

- Ninebot 资产库继续自研。
- 前端面板参考 ComfyUI-Sidebar-Gallery 和 ComfyUI-Gallery。
- 结果回收入库参考 ComfyUI-Gallery。
- 模型资产参考 ComfyUI-Lora-Manager。
- 工作流模板兼容 ComfyUI 官方 `example_workflows/`。
- DAM 体验参考 SmartGallery DAM。
